# OpenClaw Gateway User Units (desktop)

These three systemd **user** units are generated by OpenClaw's own installer and
captured here so the desktop can be rebuilt without re-running it. They are
desktop-only: every `ExecStart` and `PATH` hardcodes
`/home/blueaz/.openclaw/tools/node-v22.22.0/...`, which exists on no other
machine.

They previously lived in `sway/.config/systemd/user/`, which meant any host that
stowed `sway` linked all three. On the Z13 that produced three linked units
pointing at a nonexistent Node install. They are kept out of every stow package
on purpose — install them explicitly, here, only on the desktop.

## Units

| Unit | Profile | State dir |
|---|---|---|
| `openclaw-gateway.service` | default | `~/.openclaw` |
| `openclaw-gateway-localollama.service` | `localollama` | `~/.openclaw-localollama` |
| `openclaw-gateway-ollama-local.service` | `ollama-local` | `~/.openclaw-ollama-local` |

All three listen on `OPENCLAW_GATEWAY_PORT=18789`, so only one may run at a time.

## Install

```bash
for u in ~/.dotfiles/machines/desktop/openclaw/*.service; do
  ln -sf "$u" ~/.config/systemd/user/
done
systemctl --user daemon-reload
```

Then enable exactly one:

```bash
systemctl --user enable --now openclaw-gateway.service
```

## Verify

```bash
systemctl --user list-unit-files 'openclaw*'
systemctl --user status openclaw-gateway.service
ss -ltnp | grep 18789
```

## Open question: two identical ollama profiles

`openclaw-gateway-localollama.service` and `openclaw-gateway-ollama-local.service`
are byte-identical apart from the profile name and its state directory
(`localollama` vs `ollama-local`). That is the signature of a profile rename
where the old unit was never removed.

Nothing in this repo references either name, so the live one can only be
identified on the desktop:

```bash
ls -d ~/.openclaw-*
systemctl --user is-enabled openclaw-gateway-localollama.service \
                            openclaw-gateway-ollama-local.service
```

Whichever has no state directory and is not enabled should be deleted from this
directory. Both are kept for now rather than guessing.
